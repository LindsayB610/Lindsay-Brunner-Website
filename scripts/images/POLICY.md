# Supported image source policy

`images:policy` parses authored JS/TS/JSX/TSX modules, first-party static scripts, HTML/Markdown inline scripts (including unused Hugo templates), style blocks, style attributes and CSS. Hugo actions are replaced with inert tokens before parsing. JSON/JSON-LD/importmap scripts remain data. Parse failures fail the build. Generated `static/react/` bundles are excluded by purpose: their authored modules are scanned. Tests, tools, dependencies and caches are outside the source roots. Source symlinks fail rather than silently skipping their targets.

The gate rejects raw JSX img/picture/source nodes, DOM image construction, source/source-set writes, dynamic computed writes/calls, aliased DOM mutation methods, HTML insertion, code evaluation, reflective writes and network image URLs in CSS. Literal non-image DOM creation and attributes remain supported. CSS fragment references and font URLs remain supported. Dynamic background/mask image properties require review. This is a deliberately bounded syntax policy, not whole-program data-flow analysis or a security sandbox: new metaprogramming/import mechanisms require explicit review rather than a claim that arbitrary JavaScript can be proven safe.

`policy-exceptions.mjs` contains exact file + owning symbol + AST node text + kind entries, with reasons. Each exception can match once per source unit. No adapter file is exempt. New sinks in a registered file, duplicate sinks and changed expressions fail tests. Existing exceptions cover the sole React image JSX node, the shared responsive source assignments, the original-dialog assignment and the existing Turnstile script-loader assignment. Altered adapter semantics still require normal review and behavior tests; matching one assignment is not a proof of its surrounding logic.

Canonical build order includes source policy after preparation and before Vite, and rendered inline/CSS policy after finalization through `test:images`. Neither launches a browser. `test:images:policy` is a source-only negative fixture leaf.

`test:images:runtime` is a separate no-build test against completed `public` and its matching manifest. It uses one Playwright bundled headless Chromium process, fresh contexts, blocked external traffic, disabled HTTP cache and an ephemeral localhost server with no compression and `Cache-Control: no-store`. It never supplies a GUI browser channel or executable. It records selected response paths/body byte counts, cold duplicate requests, rotation, lazy originals, open/close/reopen and cleanup in `.generated/images/runtime-report.json`. The unused zoom shortcode is rendered as a virtual in-memory route using the real shortcode and image finalizer. The suite keeps failing assertions and continues independent scenarios to report all defects. Signal and finally handlers close contexts/browser/server; owned process IDs are checked after closing.

Before an authorized push/release, run `npm run deploy:gate` (the full release gate) or `npm run test:images:release` (the focused image bundle) locally against the final source. A green earlier build is insufficient after edits. `.github/workflows/image-runtime.yml` runs the same canonical build and a separate runtime step on pull requests, main pushes and manual dispatch, installing only the dedicated headless shell. Netlify runs `npm run deploy:gate` before publishing in every Git build context. The gate installs only the dedicated headless shell, runs the full site suite (including image fixtures), then image presentation, image runtime and final rendered layout checks. Any failed, interrupted or unstartable stage returns nonzero and blocks publication. The final checks use local `public` output; `VISUAL_AUDIT_ORIGIN` is removed from the gate environment. No build runs after these final checks. GitHub CI remains an independent signal, not the production publication gate.

Use Git continuous deployment for releases. Manual API/CLI uploads without a build bypass Netlify's build command and are not an approved release path. Administrator changes can disable any repository gate; this is not an account-level ban on manual publication.

Runtime checks are behavioral, not an LCP benchmark. Task05 owns the seven-run before/after timing comparison with the frozen baseline protocol. The runtime matrix does not establish broad visual approval, field performance or live CDN headers.

## Automatic React manifest membership

Preparation calls the build-only `runtime-sources.mjs` scanner over `src/` JS/TS modules. `ResponsiveImage` and `RetainedResponsiveImage` usages with root-relative local string literals (including JSX expression strings and no-substitution templates) automatically enter the lean browser manifest. Named import aliases are recognized. Missing files, unsupported URL/query forms, missing src, spread props, and unresolved expressions fail preparation with source file/line/column. Ordinary image authors do not edit optimizer path lists. The helper and its registration metadata are never imported by browser modules; the existing manifest projection strips build paths and hashes.

Dynamic data remains deliberately bounded: the existing logo component's `logo.src` reads the literal `LOGOS[].src` inventory; the testimonial component's two forwarding sites read `testimonials[].avatar`. These are explicit file/component/expression contracts, with owning-function checks on testimonial forwarding, not general variable-flow inference. Their array entries must have one literal source and no spreads; missing sources fail. The retained portrait adapter has one exact internal spread-forwarding seam. New dynamic components, forwarding patterns, namespace imports, re-export chains or metaprogramming need a reviewed contract rather than automatic JavaScript inference. Changes to the registered data flow still require code review; the registration is not a proof of arbitrary surrounding logic.

The source gate rejects shorthand dynamic image style members and CSSOM `setProperty` calls with image-bearing or unresolved property names. Direct literal non-image CSSOM writes remain usable. Extraction/destructuring of CSSOM mutation capabilities is rejected rather than alias-tracked. Explicit Object/Reflect write APIs are normalized across dot and literal-bracket access; their extraction/destructuring also fails, including inside adapter files.

`tests/image-runtime-sources.test.mjs` creates an unrelated raster and authored component in an isolated root, discovers its source, projects the lean manifest and executes the real transpiled React adapter with server rendering. Negative fixtures cover missing/unresolved/unsupported URLs, spreads and corrupted registered data. No browser is needed for this regression.
